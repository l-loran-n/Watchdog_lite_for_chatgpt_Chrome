# Безопасность и конфиденциальность

## Область действия

Эта сборка Watchdog Lite работает **только внутри браузера Chrome** на `chatgpt.com`. В неё не включены Telegram, WebSocket Bridge, сервер, VPN, API-ключи, механизм удалённого управления компьютером и сторонние аналитические сервисы.

**Никакая автоматизация с генеративной моделью не гарантирует безопасность побочных действий.** Расширение инициирует команды продолжения, но не контролирует все инструменты и действия, которые может выполнять ChatGPT в подключённых сервисах.

## Что видит и сохраняет расширение

1. Сценарий на `chatgpt.com` анализирует видимую часть страницы: редактор, состояние генерации, сообщения и техническую строку `WD6_STATUS`. Это необходимо для выполнения основной функции.
2. В `chrome.storage.local` сохраняются только метаданные: URL и названия выбранных чатов, идентификаторы вкладок и запусков, фазы, счётчики, служебные статусы, ошибки. Текст самой переписки туда не копируется.
3. Расширение не обращается к чужим доменам и не содержит явных сетевых запросов `fetch`/`XMLHttpRequest`/`WebSocket`.
4. Технические сообщения **отправляются в ChatGPT** как обычные сообщения пользователя. Это не «полностью офлайн» приложение.
5. URL чатов и их названия могут быть конфиденциальны. Защищайте Chrome-профиль и резервные копии пользовательских данных.

## Реализованные ограничения

- Ограничение host permissions доменом `chatgpt.com`.
- Нет `<all_urls>`, чтения cookies, сетевого перехвата или возможности выполнения произвольного кода извне.
- `GET` из вкладки видит только задания этой вкладки; команды `ADD`, `REMOVE`, `STOP_ALL` разрешены только UI расширения.
- Сервис-воркер сверяет настоящую вкладку, уникальный ID запуска и URL; поля `PATCH` проходят белый список с проверкой типов и длины. Запрещено менять через `PATCH` URL, ID, таб или идентификатор запуска.
- Новые вкладки автоматически не создаются, автоматическая перезагрузка отключена.
- Не выполняется бесконечная повторная отправка неоднозначно доставленного сообщения; ограничены попытки `REPAIR`/`RESCUE`.
- За один запуск — не более 100 сообщений, одновременно не более 20 отслеживаемых чатов.
- В интерфейсе применяется `textContent`, а не `innerHTML`, чтобы не интерпретировать название или сообщение как HTML.
- Есть ручные остановки по одному диалогу и для всех диалогов.

## Что остаётся риском

- **Дублирование действий**: даже новый `COMMAND_ID` не мешает модели снова выполнить уже совершённое действие. Watchdog не может гарантировать идемпотентность внешних операций.
- **Ошибки интерфейса ChatGPT**: изменение DOM может привести к неправильному определению редактора, отправки или статуса. При непонятном состоянии **останавливайте** расширение вручную.
- **Prompt injection**: содержимое веб-страниц и самих чатов может повлиять на ответ модели; проверка формата `WD6_STATUS` не является криптографическим подтверждением выполнения.
- **Секреты в чате**: расширение не загружает их отдельно, но любой текст, набираемый или отправляемый в ChatGPT, обрабатывается согласно настройкам и условиям самого сервиса ChatGPT.
- **Chrome-профиль и другие расширения**: уязвимости браузера или иное вредоносное расширение могут обойти изоляцию.
- **Непрерывная работа**: закрытый браузер, сон компьютера, ограничения фоновых вкладок и изменение интерфейса могут прерывать цикл.

## Правила безопасной эксплуатации

Не оставляйте выполнение без присмотра, если задача может удалить информацию, изменить права доступа, затронуть финансы или отправить сообщения третьим лицам. Используйте резервные копии, тестовый контур и операции с подтверждением. Отдельно проверяйте результат в целевой системе — `PASS` является **сообщением модели**, а не независимой проверкой.

Не публикуйте экспорт Chrome, `chrome.storage.local`, резервные копии чатов, cookies, токены доступа, файлы `.env`, ключи SSH/TLS или логи с персональными данными. Такие файлы намеренно исключены через `.gitignore`; дополнительные проверки необходимы перед каждым коммитом.

## Сообщить об уязвимости

Не публикуйте секреты и приватные переписки в общедоступных issues. Используйте приватное сообщение владельцу репозитория либо GitHub Private Vulnerability Reporting, если оно настроено. Не прикладывайте полные URL персональных чатов.
